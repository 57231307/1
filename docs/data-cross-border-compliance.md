# 数据跨境传输合规评估

> 版本：V15 P2 B08-P2-1
> 评估日期：2026-08-01
> 依据：《中华人民共和国个人信息保护法》《数据安全法》《网络安全法》《个人信息出境标准合同办法》

## 一、评估范围

本次评估覆盖纺织 ERP 系统中三类涉及数据出境的数据流，识别其跨境传输路径、数据主体、数据类型与合规风险：

1. **SMTP 邮件服务数据流**：系统通过 SMTP 协议向客户、供应商、内部员工发送业务通知邮件（订单确认、交付提醒、对账单、报价单等）。邮件正文与附件可能包含客户联系人姓名、手机号、邮箱、合同金额、交付地址等个人信息与商业数据。
2. **Kafka 消息队列数据流**：系统通过 Kafka 异步解耦业务事件（订单状态变更、库存变动、生产流转卡状态、能耗采集等）。消息体携带订单号、客户 ID、设备编号、产量数据等业务数据，若 Broker 部署在境外节点，则构成数据出境。
3. **数据库备份数据流**：系统定期对业务数据库（PostgreSQL/MySQL）执行全量与增量备份，备份文件包含客户档案、供应商档案、员工信息、工资明细、合同条款等敏感数据。若备份对象存储位于境外区域，则构成数据出境。

## 二、现有跨境数据流识别

### 2.1 SMTP 邮件服务跨境风险

当前系统邮件服务默认配置指向境外邮件服务提供商（如 AWS SES、SendGrid、Mailgun 等），其 SMTP 中转服务器位于境外数据中心。具体风险：

- **个人信息出境**：邮件收件人姓名、手机号、邮箱地址、订单交付地址属于个人信息，通过境外 SMTP 中转即构成个人信息出境，需满足《个人信息保护法》第 38-39 条规定的出境条件。
- **商业秘密泄露风险**：邮件附件中的报价单、合同条款、对账单涉及企业商业秘密，经境外服务器中转存在被境外司法管辖调取的风险。
- **日志留存合规风险**：境外邮件服务商通常在境外留存发送日志（含收发件人、时间、IP），日志含个人信息且不受境内监管，违反《数据安全法》数据属地管理要求。
- **无法满足重要数据本地化**：若企业被认定为关键信息基础设施运营者，邮件中涉及的重要数据出境需通过国家网信部门安全评估，当前架构无法满足。

### 2.2 Kafka 消息队列跨境风险

当前 Kafka 集群若采用境外云厂商托管服务（如 AWS MSK、Confluent Cloud 境外区域），存在以下风险：

- **业务数据批量出境**：Kafka 主题中流转的订单事件、生产工序记录、能耗数据属于企业核心业务数据，Topic 数据同步至境外 Broker 即构成批量数据出境。
- **元数据出境**：Kafka Connect / Schema Registry 同步的 Topic 名称、消费组、Schema 定义等元数据暴露业务结构与数据模型，存在商业秘密泄露风险。
- **跨境延迟与可用性风险**：境内外网络链路存在不可控延迟与中断风险，可能导致生产流转卡状态、订单状态事件丢失，影响车间生产连续性。
- **监管调查响应困难**：发生数据安全事件时，境外 Broker 数据获取需跨境司法协助，无法满足《数据安全法》第 32 条应急响应与调查配合要求。

### 2.3 数据库备份跨境风险

当前数据库备份若存储于境外对象存储（如 AWS S3 海外区域、Azure Blob 海外区域），存在以下风险：

- **全量敏感数据出境**：备份文件为业务数据库完整快照，包含客户档案、员工身份证号（B08-P2-3 预留字段）、工资明细（含个税代扣代缴金额 B08-P2-7）、合同条款等高敏感数据，单次备份即构成大规模敏感数据出境。
- **个人信息出境数量触发申报**：备份含员工与客户个人信息，数量极易超过《个人信息保护法》第 38 条规定的 100 万人阈值，必须申报安全评估。
- **备份留存周期风险**：境外对象存储通常按配置长期留存历史备份，出境数据无法按要求删除，违反"可追溯、可销毁"原则。
- **加密密钥属地风险**：若使用境外 KMS 托管加密密钥，密钥与密文分离存储于不同法域，境内外主体配合方可解密，实质削弱数据控制权。

## 三、数据本地化策略

为消除上述跨境风险，系统引入 `DATA_LOCALITY=cn-only` 配置，强制所有数据存储与中转节点位于中华人民共和国境内（不含港澳台）。

### 3.1 配置项说明

| 配置项 | 取值 | 说明 |
|--------|------|------|
| `DATA_LOCALITY` | `cn-only` | 强制数据本地化模式，所有数据存储、消息中转、邮件中转节点必须位于境内 |
| `SMTP_PROVIDER_REGION` | `cn` | 邮件服务提供商区域限定为境内节点 |
| `KAFKA_BROKER_REGION` | `cn` | Kafka Broker 部署区域限定为境内节点 |
| `DB_BACKUP_REGION` | `cn` | 数据库备份对象存储区域限定为境内 |

### 3.2 启用方式

在 `.env` / 环境变量中设置：

```
DATA_LOCALITY=cn-only
SMTP_PROVIDER_REGION=cn
KAFKA_BROKER_REGION=cn
DB_BACKUP_REGION=cn
```

系统启动时校验上述配置，若检测到 `DATA_LOCALITY=cn-only` 而任一服务区域配置为非 `cn`，则启动失败并输出合规告警日志，防止误配导致数据出境。

### 3.3 数据驻留校验

- 应用层在建立 SMTP / Kafka / 对象存储连接时，校验目标节点 Region 是否为 `cn`，非境内节点拒绝连接。
- 数据库备份任务执行前，校验备份目标存储桶 Region 标签为境内，否则中断备份并告警。
- 定期（每日）扫描存量配置，发现区域漂移自动告警通知安全管理员。

## 四、境内服务商要求

为配合 `DATA_LOCALITY=cn-only` 策略，需将境外服务商替换为境内合规服务商：

### 4.1 邮件推送服务替换（阿里云邮件推送 DirectMail）

- **替换目标**：阿里云邮件推送（DirectMail），节点位于境内（杭州/北京/深圳等 Region）。
- **接入方式**：通过阿里云 SMTP 接口或 API 发送，发信域名需完成 ICP 备案与 SPF/DKIM/DMARC 配置。
- **合规优势**：发信日志留存于境内，可配合监管调查；支持发信频率与收件人白名单管控，降低个人信息滥用风险。
- **迁移要点**：原境外邮件服务商的发送日志应在迁移前导出并归档至境内存储，迁移完成后关闭境外账号并销毁境外留存数据。

### 4.2 Kafka 消息队列替换（阿里云 Kafka / 自建境内集群）

- **替换目标**：阿里云消息队列 Kafka 版（境内 Region），或自建 Kafka 集群部署于境内 IDC。
- **接入方式**：保持现有 Kafka 协议兼容，仅需切换 Broker 接入点与认证凭证；消费组、Topic、Schema 配置平移。
- **合规优势**：消息体与元数据全量留存于境内，数据主权可控；支持按 Topic 粒度审计访问行为。
- **迁移要点**：迁移期间双写双读校验数据一致性；迁移完成后销毁境外 Broker 数据并关闭境外集群。

### 4.3 数据库备份存储替换（阿里云 OSS 境内 Region）

- **替换目标**：阿里云对象存储 OSS（境内 Region，如 oss-cn-hangzhou）。
- **接入方式**：备份脚本将全量/增量备份文件上传至 OSS 境内桶，启用服务端加密（SSE-KMS，使用境内 KMS 托管密钥）。
- **合规优势**：备份文件加密密钥与密文同驻境内，数据控制权完整；支持备份生命周期管理与到期自动删除，满足"可销毁"要求。
- **迁移要点**：历史境外备份应回迁境内后销毁境外副本；迁移过程使用加密通道传输，避免传输途中二次出境。

## 五、合规风险与缓解措施

### 5.1 风险一：个人信息出境未履行法定程序

- **风险描述**：若未能完全替换境外服务商或区域漂移未被及时发现，仍存在个人信息出境情形，未履行安全评估/标准合同/认证程序将面临《个人信息保护法》第 55-56 条处罚（警告、罚款、责令改正、停业）。
- **缓解措施**：
  1. 启用 `DATA_LOCALITY=cn-only` 强制校验，启动期阻断非境内连接；
  2. 部署区域漂移监控告警，每日扫描并通知安全管理员；
  3. 建立出境数据台账，对存量历史出境数据完成回迁与销毁记录存档。

### 5.2 风险二：重要数据 / 核心数据误判出境

- **风险描述**：纺织行业订单、产能、能耗数据若被认定为重要数据或核心数据，出境需通过国家网信部门安全评估，误判出境将构成重大合规事件。
- **缓解措施**：
  1. 开展重要数据识别与目录编目，明确出境数据分级；
  2. 对涉及重要数据的 Kafka Topic、数据库表实施访问权限最小化与审计留痕；
  3. 全量数据本地化存储，从架构上消除出境场景。

### 5.3 风险三：服务商 SLA 与可用性下降

- **风险描述**：境内服务商替换后，邮件送达率、Kafka 吞吐、备份性能可能低于原境外服务商，影响业务连续性。
- **缓解措施**：
  1. 替换前完成压测与可用性验证，明确 SLA 指标并写入合同；
  2. 邮件服务配置多发信域名与备用发信通道，Kafka 配置跨可用区容错，备份配置多副本冗余；
  3. 建立服务商故障应急预案与降级策略，确保业务连续性不受单点故障影响。

## 六、评估结论

经评估，当前系统 SMTP 邮件服务、Kafka 消息队列、数据库备份三类数据流在采用境外服务商时存在个人信息出境、重要数据误判出境、监管响应困难等合规风险。

通过实施 `DATA_LOCALITY=cn-only` 数据本地化策略，将邮件推送替换为阿里云 DirectMail、Kafka 替换为阿里云 Kafka / 自建境内集群、数据库备份替换为阿里云 OSS 境内 Region，可从架构层面消除数据出境场景，满足《个人信息保护法》《数据安全法》《网络安全法》对数据属地管理与个人信息出境的程序性要求。

建议在 V15 P2 阶段完成上述服务商替换与配置强制校验上线，并建立区域漂移监控、出境数据台账、服务商 SLA 保障三项长效机制，持续维持数据跨境传输合规状态。
