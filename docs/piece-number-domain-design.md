# 匹号/缸号领域模型设计（胚布-染色全链路）

> 2026-09-05 依据用户业务规则确立。本设计是匹号管理的唯一权威依据，
> 实施前完整阅读。分期任务见 .monkeycode/doto.md。

---

## 一、核心领域规则（用户确认，不可违背）

1. **生产后的胚布产品必须有匹号（生产匹号）**：胚布完成生产即逐匹登记，
   同时记录**机台号**（机台号只在生产胚布时存在，胚布没有缸号）。
2. **生产匹号与染色匹号不通用**：
   - 生产匹号：只在生产环节使用；
   - 染色匹号：染色完成后生成，在**入库/外发/销售/出库/对账**都必须体现。
3. **外发染色**：有匹号的胚布外发染色；**染色完成后必须有缸号**
   （缸号只有外发染色后才存在）。
4. **净布工艺例外**：净布工艺的外发不需要缸号；其他外发工艺必须在染色
   之后才能进行外发（即必须已有缸号）。
5. 生产报工时**逐匹登记**（每匹记录长度/重量等），是生产匹号的生成时机。

## 一·补充、查布（检验）规则（用户确认）

1. **胚布查布**：生产环节对胚布**每一匹都查**（100% 全查），逐匹精确记录：
   对应产品、匹号、疵点、重量、查布时间等。
2. **成品查布**：成品入库前也要做类似检验流程，但为**抽查**（非逐匹全查）。
3. 机台号记录内容：**什么人开的机器**（开机人）+ **什么时候入库的胚布仓库**
   （胚布入库时间）。
4. 仓库类型约束：**胚布仓只能存放未染色、未做工艺的胚布；成品仓只能存放
   染色后或做工艺后的成品**。匹/布入错类型仓库必须拒绝。

## 二、实体与标识

| 标识 | 产生时机 | 归属阶段 | 关联 |
|------|---------|---------|------|
| 生产匹号 + 机台号 | 生产报工（逐匹） | 生产环节专用 | 胚布产出 |
| 缸号 | 外发染色完成 | 染色后全链路 | 委外回仓/染色批次 |
| 染色匹号 | 染色完成回仓入库 | 入库/外发/销售/出库/对账 | lineage → 生产匹号 |

- `inventory_piece` 现表以 (dye_lot_id, piece_no) 唯一，dye_lot_id 非空——
  只能承载染色匹号。需扩展：`piece_type`（greige 生产匹 / dyed 染色匹）、
  `machine_no`（机台号，仅生产匹）、`dye_lot_id` 改可空（生产匹无缸号）。
- 生产匹 → 染色匹的血缘用 `parent_piece_id` 表达（染色回仓时建立）。

## 三、状态与校验规则

| 动作 | 校验 |
|------|------|
| 生产报工 | 逐匹必填：匹号/机台号/长度（重量宽度克重可选） |
| 外发染色发料 | 引用的必须是生产匹（piece_type=greige） |
| 染色回仓入库 | 必须生成染色匹号 + 缸号（必填）；净布工艺除外 |
| 出库/销售/外发(非染色工艺) | 引用染色匹（piece_type=dyed 且有缸号）；净布胚布除外 |
| 对账单据 | 携带染色匹号/缸号字段 |

### 编号语义（2026-09-05 用户二次确认，代码已按此实现）

- **生产匹 = 生产单号下的产品生产出来的第 * 匹**：
  `inventory_piece.batch_no` 记生产单号（production_order.order_no）；
  生产匹 piece_no 由报工逐匹登记传入；仅挂胚布仓。
- **染色匹 = 缸号/染色批次号染色后的第 * 匹**：
  `piece_no = {缸号}-{seq:03}`、`batch_no = 缸号`、`piece_seq` 同缸递增
  （与验布打卷 generate_next_piece_no 同语义）；净布外发的无缸号胚布匹
  例外用回仓单号编号（{receipt_no}-P01）。
- 缸号档案 batch_dye_lot 在染色回仓时 find_or_create 自动建档
  （回仓是缸号的产生时机；历史上无建档入口导致染色链路走不通）。
